## Visual grammar

Stop treating the ten boxes as sealed islands. They may survive as **subtle visual
regions**. They must not dictate connectivity.

Arrange the sheet around electrical flow:

```text
 USB / POWER ENTRY
        |
        v
 protection -> current sense -> 5V_SYS ----------------+
        |                                              |
        +-- buck -> 3V3                                |
        +-- mic rail                                   |
        +-- NFC rail                                   |
        +-- LED branch protection                      |
                                                       |
                       +-------------------------------+
                       v
                +--------------+
 AUDIO / PDM -> |    RT1062    | -> LED drive
 boot / debug ->|              |
                +------+-------+
                       |
                     K1BR
                       |
                       v
                +--------------+
                |   ESP32-S3   |
                | radio/service|
                +--+--------+--+
                   |        |
          service USB    NFC / control

 motion / ownership / validation sit beside their owners
```

Local circuits become visible wiring, not distant same-named labels.

Power (from `architecture/POWER-ARCHITECTURE.md`): USB-C → CC / VBUS → TVS → U1 eFuse →
shunt / INA226 Kelvin → `5V_SYS` → TPS62913 / mic rail / NFC rail / TPS2561 LED
branches. Disconnected `5V_SYS` labels are not a power tree.

Audio: RT1062 ↔ series / options ↔ ADC6120 ↔ input / clock, with PDM alternatives drawn
as forks and the XOR rule beside them.

NFC: S3 control → ST25R3916B → RF network → antenna connector; matching parts tight
around the ST device; `TUNE_TBD` stated.

Motion: visible common I²C, ownership legs, interrupt route, power / decoupling.

K1BR: compact visible bus between RT and S3.

USB: connector → ESD → optional series → MCU, not two labels separated by a blank page.

The RT1062 is already multipart. Keep the same `U6` BOM device. Space units by
function (power/DCDC, audio/SAI/PDM, K1BR/control, LED, boot/reset/debug,
GPIO/options) so support circuitry wires locally. Decoupling sits beside the rail it
serves.
